# 每个人给自己的AI使用的提示词

先共同提供：最终计划书、PROJECT_CONTEXT.md、API_CONTRACT.md、DATA_SCHEMA.md及当前相关代码。

## 通用模板

我们四人开发知味厨房。请先阅读上述文件。我负责【角色】，只修改【目录】。今天完成【任务】，验收办法【输入与预期】。先说明改动范围，再实现和运行必要检查。保持共同格式；跨模块变更先说明影响。区分fixture、实际模型调用和真实程序结果。最后给出修改文件、运行方法、实际通过的检查及未完成项。

## A首个任务

在mobile/准备Android客户端基础工程，先让真机运行，再做需求输入、菜单、计划、执行四页的最小导航。公共接口按契约，缺少实际服务时明确使用fixture。不要生成一套独立后端。

## B首个任务

在server/准备Python业务入口和依赖说明，实现/api/v1/health并让手机能访问。维护api/、db/和入口；为C、D预留可导入模块。不要代写他们的算法与菜单逻辑。先给出启动命令和可验证响应。

## C首个任务

在server/planner/先读取data/demo_cases.json，验证ID、依赖和资源。以basic_three_dishes为共同样例实现基础可行安排及独立冲突检查，再扩展倒排和重排。too_short案例应识别固定前置链超过可用时间；UNKNOWN不能说无解。保留真实检查日志。

## D首个任务

在server/ai/建立可配置模型接口，按约定结构提议菜单；密钥仅从后端环境读取。准备人工核对菜谱，不把测试任务时长当真实菜谱依据。先从小范围候选生成并检验，失败保留原需求，不虚构成功请求。
